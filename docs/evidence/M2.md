## Unverified assumptions
- The live 24-bit neon appearance is not visible from this headless shell (Q1). Layout and symbols are proven by the TestBackend snapshots; truecolour remains for the human check at M4.
- The `script` pty used by the gate reports 0x0, so `--self-test-tui` draws frames with a zero-cell buffer. It proves raw-mode/alternate-screen setup, five draw calls and restore under a real pty, not visible painting at 100x36; the snapshots cover painting.
- Real keyboard delivery in a terminal emulator was not exercised (no tty). Key handling is proven against constructed crossterm `KeyEvent` values, including the release kind.
- Real file persistence across a process restart is M4/N4; M2 proves the shell's store wiring with a recording stub and the no-persist isolation with the real binary.

## Limitations and known issues
- `--frame` is parsed, validated and threaded into `Args`, but no pixel changes before the M3 effect renderer exists.
- `--demo` and `--demo-merge` show the seed-42 board and force the memory store; the immediate merge capture board is pinned in M3 (Q4).
- The live loop advances state by a fixed `1/fps` step instead of a measured elapsed time (Q8); M3 needs a measured, clamped `dt` for effects.
- A live run without a terminal (for example `cargo run` in this agent shell) cannot initialise the TUI. The gate uses the pty self-test instead.

## Deviations and near-misses
- The footer warning decrements by each `dt` rounded up to whole milliseconds, so 90 frames of exactly 33 ms (90 x 33 = 2970 ms of nominal time) already clear it. This keeps the reviewer's "3000 ms = 90 frames at 30 fps" check true for both 33 ms and 33.333 ms frame steps; the warning can disappear up to one frame early.
- `--render-once` and `--self-test-tui` always use `MemoryStore`, even without `--no-persist`, so a preview can never read or write the real best score. This is stricter than R3 requires and keeps previews deterministic.
- `--render-once` renders a fixed 100x36 frame regardless of the real terminal size, as R6 requires; the 60x30 snapshot is exercised through the renderer test, not a CLI flag.
