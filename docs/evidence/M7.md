## Limitations and known issues
- `two_merges_keep_two_waves` triggers the two merges on the `Effects` layer (cells 0 and 5) because no single 2048 move can produce merge destinations 0 and 5: on a Left move every destination is in column 0, and cell 5 needs a second merge in row 1. The update path is covered separately by `one_move_with_two_merges_keeps_two_waves` (cells 0 and 12 from one Left move). Q12 records this.
- The tile-label layer paints its whole 7-cell, 1-row rect with the tile style, so a ripple glyph that overlaps an occupied card's label row takes that tile's foreground colour (for example the `2` at cell 9 during its 180 ms flash). The pinned cells in the review are all outside label rows, and a digit still wins in its own cell; the effect colour on those rows is not pinned by SPEC §5.4.
- `make check` output is longer than the 20 000-byte evidence cap, so the "R8 make check", "M7 gate", "R2 F2 make check" and "M7 gate round 2" blocks end with ev.sh's `...[truncated, N bytes total]` marker; the exit code line is still recorded and the per-target counts are in "R2 F2 test counts". FU2 in the review notes the same cap.
- The round-2 change is colour-only, so the three text fixtures and the text e2e capture cannot show it: the fade is proven by `ripple_colour_fades_with_age` reading buffer cells (fg), and F2 proves the text did not move (0-line fixture diff).
- The fixture diffs are multiple lines per fixture (6/13/19), not one line: replacing a 450 ms ring with a 900 ms reflecting ripple changes glyph cells on every board row. Each fixture still appears exactly once in `git diff --numstat` and every changed line is a ripple/board-symbol row, never a non-effect row such as `SCORE`.
